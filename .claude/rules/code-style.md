# Правила: стиль кода и видимость

## 1. Уровни видимости в Dart

В Dart их **два**, а не три:

| Уровень | Как пишется | Что видно |
|---|---|---|
| public | `loadItems` | всему приложению |
| library-private | `_loadItems` | только этой библиотеке — файлу и его `part`-файлам |

Аналога `internal` из Kotlin/C#/Swift нет. Его частично заменяют аннотации
`package:meta`, но это **маркеры для анализатора, а не защита**:

| Аннотация | Смысл | Когда в этом проекте |
|---|---|---|
| `@protected` | предназначено только для наследников | члены базовых классов (`BaseBloc`), которые зовут блоки-наследники |
| `@visibleForTesting` | public только ради теста | вместо того, чтобы делать метод public «чтобы протестировать» |
| `@internal` | public внутри пакета, но не для потребителей | **не используем**: имеет смысл только для публикуемых пакетов |

Отсюда практический вывод: «сделать internal» в этом проекте означает **сделать `_`**,
а если членом пользуется другой файл — пересмотреть, туда ли положен код.

## 2. Порядок членов класса

Сверху вниз — от того, что нужно вызывающему, к тому, что нужно только самому классу.

1. `static const` / `static final`;
2. поля экземпляра: **сначала public, потом `_`**;
3. конструкторы: обычный, затем именованные и `factory`;
4. public-геттеры и сеттеры;
5. переопределения фреймворка (`@override`) — **в порядке жизненного цикла**, не по алфавиту;
6. остальные public-методы;
7. private-методы (`_`);
8. private-классы этого файла — **в конце файла**, после публичного.

```dart
class TrackCard extends StatelessWidget {
  static const double _coverSize = AppSize.s56;   // 1

  final Track track;                              // 2 — public: приходит снаружи
  final VoidCallback onTap;

  const TrackCard({super.key, required this.track, required this.onTap});  // 3

  @override
  Widget build(BuildContext context) { ... }      // 5

  String _subtitle(BuildContext context) { ... }  // 7
}

class _CoverPlaceholder extends StatelessWidget { ... }   // 8
```

Порядок жизненного цикла для `State`:
`initState` → `didChangeDependencies` → `didUpdateWidget` → `build` → `dispose`.
`dispose` **всегда последний из переопределений**, даже если он короткий: так видно,
что освобождается, рядом с концом класса.

Конструктор идёт **после** полей — так принято во всём этом коде (`AppColors`, `Track`,
диалоги, `RemoteImage`). Лint `sort_constructors_first` намеренно не включён: он требует
обратного и переворошил бы весь проект без выгоды.

## 3. Что должно быть public, а что — private

### Правило по умолчанию

**Всё private, пока не доказано обратное.** Член становится public только если у него есть
вызывающий **вне этого файла**. Не «может понадобиться», не «вдруг пригодится» — есть
конкретный вызов.

Проверка механическая: убери `_`-кандидата и найди вызовы вне файла.

```bash
# есть ли у публичного члена вызывающие, кроме собственного файла
grep -rn "\.loadItems(" lib | grep -v "features/home/domain/music_api_repository.dart"
```

Пусто → член обязан быть private. Public-член без внешних вызывающих — это не «запас»,
а расширенный контракт: его придётся поддерживать, его увидит автодополнение, и кто-нибудь
им однажды воспользуется в обход правил.

### По типам файлов

| Файл | Public — обязано быть | Private — обязано быть |
|---|---|---|
| **Блок** | конструктор, `@override close()` | **всё остальное**: обработчики событий, репозитории, дебаунсеры, токены отмены, вспомогательные вычисления |
| **Стейт (freezed)** | поля и `copyWith` (генерация), `factory X.initial()` | — |
| **События, ui-эффекты** | классы и их поля | — |
| **Виджет** | параметры (`final`, приходят снаружи), конструктор, `build` и прочие overrides, `createState` | контроллеры, фокус-ноды, флаги анимации, обработчики, вспомогательные виджеты файла |
| **Репозиторий** | методы, которые зовёт блок (возвращают `Result`) | сборка запроса, разбор ответа, маппинг, `_apiService`, кэш |
| **Сервис** | контракт, которым пользуются потребители из DI | состояние, подписки, внутренние шаги инициализации |
| **DAO** | методы, которые зовёт репозиторий фичи | запросы-помощники, маппинг entity |
| **Модель / DTO** | поля, `fromJson`, `toJson`, маппинг `toDomain()` | — |
| **Класс-неймспейс констант** | `static const` поля | конструктор: `const AppSize._();` — чтобы нельзя было создать экземпляр |
| **Extension** | то, ради чего он написан | вспомогательные функции файла |
| **Хранилище** | типизированные геттеры/сеттеры | строковые ключи (`const _keyIsFirstLaunch`) |

### Жёсткие следствия

- **У блока не бывает public-методов, кроме `close()`.** Public-метод у блока — это
  способ поменять состояние в обход события, то есть в обход аналитики, логов и проверок.
  Всё, что «нужно дёрнуть у блока», — событие.
- **Поле `State` без `_` — ошибка.** Состояние виджета никого снаружи не касается;
  параметры лежат в самом виджете и уже public.
- **Public ради теста — не повод.** Метод остаётся private, а тест ходит через публичный
  контракт (у блока — через события). Если иначе никак — `@visibleForTesting`, а не голый
  public.
- **Член базового класса для наследников — `@protected`.** Он остаётся синтаксически
  public, но анализатор подсветит вызов со стороны.
- **Класс, у которого public всё подряд, обычно делает две вещи.** Это сигнал разделить
  его, а не расставлять `_`.

## 4. Порядок файлов и объявлений

- один публичный класс на файл; имя файла — `snake_case` от имени класса;
- приватные классы-помощники — в том же файле, **после** публичного, в порядке
  использования;
- если приватных классов больше двух-трёх или их переиспользуют — это `components/`
  (`screens.md` §5) или `core/widgets/` (`widgets.md`);
- `part` / `part of` — только для `freezed` / `json_serializable` и
  `<screen>_event.dart`. Помни: `part` расширяет библиотеку, и `_`-члены становятся видны
  между такими файлами — это осознанное исключение, а не дыра.

## 5. Именование

| Что | Как | Пример |
|---|---|---|
| файлы | `snake_case` | `track_detail_page.dart` |
| классы, enum, extension, typedef | `UpperCamelCase` | `TrackDetailPage`, `ScreenStatus` |
| методы, поля, переменные, параметры | `lowerCamelCase` | `searchQuery` |
| константы | `lowerCamelCase`, не `SCREAMING_CASE` | `static const d300ms` |
| private | префикс `_` | `_repository`, `_CoverPlaceholder` |
| булевы | вопрос-утверждение | `isLoading`, `hasCover`, `canRefresh` |
| колбэки виджета | `onX` | `onTap`, `onRefresh` |
| события блока | что произошло | `TrackTapped`, `QueryChanged` |
| ui-эффекты | что сделать | `OpenTrackDetails`, `ConfirmDelete` |

Сокращения — только общепринятые (`url`, `id`, `api`, `dto`). Не `usrRepo`, не `btn`,
не `tmp2`.

## 6. Комментарии

- комментарии и doc-комментарии **на английском**, как в существующих файлах
  (правила в `.claude/rules/` и общение с разработчиком — на русском);
- `///` — у публичных классов и неочевидных функций. У private — только если из имени
  и тела непонятно;
- комментарий объясняет **почему**, а не **что**: «что» видно в коде;
- закомментированный код не коммитится — для этого есть история (`git.md`);
- `TODO` — только с пояснением, что именно и когда: `// TODO: replace once /favorites
  endpoint is live`. Голый `TODO` — мусор.

## 7. Форматирование

- `dart format`, ширина строки 80. Руками ширину не превышать;
- висячие запятые в многострочных вызовах — тогда форматтер разложит аргументы по строкам;
- один `import` на строку, порядок секций: `dart:` → `package:` → относительные,
  внутри секции по алфавиту (проверяется линтом `directives_ordering`);
- пустая строка отделяет логические блоки метода, но не каждую строку.

## 8. Что проверяет анализатор, а что человек

Машинно (`analysis_options.yaml`):

- `library_private_types_in_public_api` — приватный тип в публичной сигнатуре;
- `prefer_final_fields` — private-поле, которое можно сделать `final`;
- `directives_ordering` — порядок импортов;
- `always_declare_return_types`, `unnecessary_parenthesis`, `prefer_final_locals`.

Линта на «public там, где должно быть private» и на порядок членов **не существует** —
это проверяет `/check` и `flutter-reviewer` по разделам 2 и 3.
