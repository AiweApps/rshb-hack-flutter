# Правила: `lib/core/misc/`

## Что это

`misc/` — прослойка между приложением и внешним миром: платформа, локальные хранилища,
сторонние SDK, обработка их ошибок. Код здесь **не знает про UI и не знает про фичи**.

Отличие от `services/`: сервис — это долгоживущий объект в DI, с состоянием, подписками,
сетью, инициализацией. Адаптер в `misc/` — тонкая обёртка без собственного жизненного цикла,
либо чистый классификатор/пробник.

**Разделение с `storage.md`:** здесь — **как устроена обёртка** (файл, ключи, соглашения
об именах). Что и где хранить, кэш, стратегии свежести, миграции, чистка при разлогине,
база данных — в `storage.md`. Заводишь новое хранимое значение — читаешь оба файла.

## Структура — подпапки по назначению

```
lib/core/misc/
  preferences/
    app_preferences.dart          # типизированная обёртка над SharedPreferences
  storage/
    secure_token_storage.dart     # обёртка над secure storage
    legacy_storage_cleanup.dart   # одноразовые миграции/чистки хранилища
  platform_version.dart           # пробы возможностей платформы (Android SDK 33+ и т.п.)
  firebase_exception_handler.dart # классификация ошибок для Crashlytics
```

Правило: как только по одной теме появляется **второй** файл — заводим подпапку.
Одиночный файл лежит в корне `misc/`.

## Что сюда относится

| Категория | Примеры |
|---|---|
| Обёртки над хранилищем | `AppPreferences`, `SecureTokenStorage`, миграции ключей |
| Пробы платформы | версия ОС, нужно ли спрашивать разрешение на пуши |
| Классификаторы ошибок сторонних SDK | `FirebaseExceptionHandler` |
| Разбор/санитизация внешних данных без домена | парсеры конфигов, чистка payload'ов |

## Соглашения

### `preferences/app_preferences.dart`

- Все ключи — приватные `const String` **в этом же файле** (`_keyIsFirstLaunch`).
  В `app_constants.dart` дублировать не нужно: ключ — деталь реализации хранилища.
- Для каждого осмысленного значения — типизированная пара геттер/сеттер
  (`bool get isFirstLaunch` / `Future<void> setIsFirstLaunch(bool)`).
  Общие `getString`/`setString` остаются как escape hatch, но новый флаг заводим
  именованным — чтобы строковый ключ не расползался по коду.
- Экземпляр резолвится через `sl<AppPreferences>()`. Прямой вызов
  `SharedPreferences.getInstance()` вне этого файла запрещён.

### `firebase_exception_handler.dart`

Один источник правды о том, какие ошибки не считаются фатальными
(сеть, загрузка картинок/SVG, `RenderFlex overflowed`) и как они классифицируются
(`network_io`, `ui_overflow`, `image_svg_load`). Новую категорию добавляем сюда,
а не в `runZonedGuarded` в `main.dart`.

### Платформенные пробы

Каждая проверка версии/возможности ОС — отдельный статический метод с говорящим именем,
описывающим **намерение**, а не версию: `shouldRequestNotificationPermission()`,
а не `isAndroid13OrAbove()`. Тогда при смене требований меняется только тело метода.

## Чего в `misc/` быть не должно

- **Extension'ов.** В `recallscope-flutter` есть `misc/extensions/` — это историческое
  расхождение, **в winescan так не делаем**. Все extension'ы живут в `lib/core/extensions/`
  (см. `extensions.md`). Единственный источник правды, один путь импорта.
- Виджетов и вообще импортов `material.dart` ради UI
  (импорт ради `debugPrint`/`Color` допустим).
- Импортов из `lib/features/**`.
- Сетевых запросов — это `core/services/api/`.
