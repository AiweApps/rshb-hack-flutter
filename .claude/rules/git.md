# Правила: git

## Главное

**Не коммитить и не пушить без явной просьбы.** Написал код — покажи результат;
решение «коммитим» принимает разработчик (`CLAUDE.md` §3).

Это не про аккуратность, а про то, что коммит фиксирует границу задачи: агент, который
коммитит сам, склеивает несвязанные правки в один коммит и делает историю бесполезной.

## Коммит = одна задача

- один коммит — одно законченное изменение. Правка экрана и «заодно переименовал в
  соседнем файле» — два коммита или, что чаще, второго вообще не должно быть
  (`CLAUDE.md` §3);
- коммит компилируется: `flutter analyze` чист, сгенерированные файлы пересобраны
  (`models.md`);
- сгенерированные файлы (`*.g.dart`, `*.freezed.dart`, `lib/l10n/app_localizations*.dart`)
  коммитятся **вместе** с исходником, из которого они получены, а не отдельным коммитом.

## Сообщение коммита

Императив, первая строка до ~72 символов, без точки в конце:

```
Add favorites screen with search
Fix track duration formatting for tracks over an hour
Move format extensions from helpers to extensions
```

- язык сообщений — английский, как и комментарии в коде (`CLAUDE.md` §10);
- тело (после пустой строки) — **зачем**, а не что: «что» видно в диффе;
- ссылки на задачу — в конце тела, если трекер используется;
- `wip`, `fix`, `.`, `123` — не сообщения.

Префиксы (`feat:`, `fix:`) в проекте не приняты. Появится требование от CI —
вводится разом для всего репозитория, а не вперемешку.

## Ветки

- работа идёт **не в `main`**. Ветка на задачу: `feature/favorites-screen`,
  `fix/track-duration`, `chore/rules-update`;
- имя ветки — латиница, `kebab-case`, по смыслу задачи;
- ветка живёт недолго: чем дольше, тем дороже слияние.

## Что не попадает в репозиторий

- секреты, ключи, keystore, `.env` (`flavors.md`);
- `build/`, `.dart_tool/`, артефакты IDE;
- закомментированный код «на память» — для этого есть история;
- личные заметки, отладочные принты, `TODO` без пояснения, что и когда.

Секрет, попавший в историю, считается скомпрометированным: нужна ротация ключа, а не
удаляющий коммит.

## Перед коммитом

1. `flutter analyze` → `No issues found!`;
2. `dart run build_runner build --delete-conflicting-outputs`, если менялись модели;
3. `flutter gen-l10n`, если менялись ARB;
4. `git diff --staged` глазами: в коммите нет ничего, чего задача не требовала —
   ни переформатированных чужих файлов, ни случайно закомиченных экспериментов;
5. `/check` по диффу (`CLAUDE.md` §7).

## Pull request

- заголовок — как сообщение коммита, тело — что сделано и что осталось;
- визуальные изменения — скриншот до/после;
- в описании явно перечислено то, что **не** вошло, и почему;
- PR не открывается и не пушится без просьбы разработчика.
