# Правила: сетевой слой

## Слои и границы

```
ApiService            — dio: транспорт. Знает про URL, заголовки, таймауты, прокси.
      ↓                 Не знает про модели и про фичи.
ApiRepository         — handleAPICall: статусы, разбор JSON, исключения → AppError.
      ↓                 Не знает про конкретные эндпоинты.
<Feature>ApiRepository — методы фичи: запрос → Result<DomainModel>.
      ↓                 Единственное, что видит блок.
Bloc                  — вызывает метод репозитория, разбирает Result.
```

Правила границ:

- **Наружу не летят исключения.** Метод репозитория всегда возвращает `Future<Result<T>>`.
  `try/catch` вокруг dio в фиче не пишется — это уже сделано в `handleAPICall`.
- **Блок не знает про dio, `Response`, статус-коды и JSON.** Он знает `Result`, `Success`,
  `Error`, `AppError`.
- **UI не знает про сеть вообще.** Ни `Result`, ни `AppError` в `presentation/` не попадают
  (кроме готового `ErrorType` в стейте — см. `errors.md`).
- `ApiService` — **один на бэкенд**, а не на репозиторий и не на фичу. Два репозитория к
  одному API получают один и тот же экземпляр из DI.

## Конфигурация — только в константах

```dart
// ❌
final musicApiService = ApiService("https://api.deezer.com/", {});
connectTimeout: const Duration(seconds: 30),

// ✅
ApiService(sl<AppFlavorService>().apiBaseUrl, const {});
connectTimeout: DurationConstant.d30s,
```

| Что | Куда |
|---|---|
| `baseUrl` | флейвор (`assets/flavors/*.json` → `AppFlavorService`), см. `flavors.md` |
| Таймауты | `DurationConstant` |
| Размер страницы пагинации, лимиты ретраев | `ApiConstants` в `app_constants.dart` |
| Пути эндпоинтов | `<feature>_api_endpoints.dart` рядом с фичей |
| Общие заголовки | `ApiService`, задаются при создании в DI |

`core/services/` — **не исключение** из `constants.md`. Литерал в ядре проживёт дольше,
чем литерал в фиче, и разойдётся между окружениями.

### Отладочный прокси

Прокси для снятия трафика — **параметр конструктора** `ApiService` со значением по
умолчанию `null`, а не поле класса и не константа в коде. Включается только для
dev-флейвора (`flavors.md`). В `prod` прокси не включается никогда, и
`badCertificateCallback` в prod-сборку не попадает.

## Как добавить запрос

Эталон — `lib/features/home/domain/`. Структура фичи:

```
lib/features/<feature>/domain/
  models/
    <model>.dart              # DTO, json_serializable
    <feature>_api_error.dart  # если бэк отдаёт свой формат ошибки
  <feature>_api_endpoints.dart
  <feature>_api_repository.dart
  <feature>_api_parser.dart   # только если формат ответа требует своего разбора
```

### Эндпоинт

```dart
class SearchFavorites extends ApiEndpoint {
  @override
  String get path => '/favorites/search';
}
```

Динамическая часть пути — через `pathBuilder` в `ApiServiceRequest`, а не интерполяцией
в `path`. Значения, подставляемые в путь, обязаны быть экранированы
(`Uri.encodeComponent`), если приходят от пользователя.

### Метод репозитория

```dart
Future<Result<List<FavoriteItem>>> loadFavorites(String query) async {
  final request = ApiServiceRequest(
    endpoint: SearchFavorites(),
    method: HTTPMethod.get,
    queryParams: {"q": query},
  );

  return handleAPICall(
    apiRequest: request,
    fromJson: (json) => MusicApiParser.getList(
      json,
      keyPath: "data",
      fromJson: FavoriteItem.fromJson,
    ),
    validateJson: (json) {
      // Бэк умеет отдавать 200 с телом ошибки — распознаём здесь.
      return null;
    },
  );
}
```

Обязательно:

- возвращаемый тип — `Future<Result<T>>`, где `T` — **доменный** тип, а не `dynamic`
  и не `Map`;
- `validateJson` заполняется, если бэк отдаёт ошибку кодом 200 в теле;
- `keyPath` соответствует реальному ответу, а не догадке. Не проверял на живом ответе —
  скажи об этом в отчёте;
- один метод = один запрос. Метод, который делает два запроса подряд и склеивает
  результат, — это уже логика, ей место в блоке или в отдельном use-case-методе
  репозитория с явным именем (`loadTrackWithAlbum`).

### Регистрация

`lib/di/di_core.dart`, `_registerApiRepositories` — по правилам `di.md`.
Репозиторий — `registerLazySingleton`, не `registerFactory`.

## Отмена и конкурентность

**Каждый запрос, который может устареть, обязан быть отменяемым.**

Типовые случаи: поиск по мере ввода, обновление вкладки, уход с экрана до ответа.

- метод репозитория принимает `CancelToken? cancelToken` и передаёт его в dio;
- блок хранит токен, отменяет предыдущий перед новым запросом и в `close()`;
- альтернатива для одного конкретного случая — `transformer: restartable()` на событии
  (см. `bloc.md`), но сетевой запрос при этом всё равно продолжает висеть, пока не отменён
  токеном.

Отменённый запрос **не** превращается в ошибку для пользователя:
`DioExceptionType.cancel` отсеивается и не показывается тостом.

Гонка ответов реальна: пользователь печатает «ea» → «easy», ответ на «ea» приходит вторым
и затирает список. Без отмены или проверки актуальности запроса это баг, который
воспроизводится на плохой сети.

## Пагинация

- номер/курсор страницы и `hasMore` живут **в стейте блока**, не в репозитории;
- размер страницы — `ApiConstants`, не литерал в вызове;
- догрузка следующей страницы — это **не** `ScreenStatus.loading` (см. `screens.md` §7),
  а отдельное поле `isLoadingMore`;
- ошибка догрузки не сносит уже показанный список: контент остаётся, ошибка — тостом или
  строкой в конце списка;
- повторный запрос той же страницы (двойной триггер скролла) отсекается в блоке.

## Авторизация

- токен хранится в secure storage (`storage.md`), **не** в `SharedPreferences`;
- подстановка заголовка — интерсептором в `ApiService`, а не в каждом репозитории;
- 401/403 обрабатывается **централизованно**: интерсептор пробует рефреш, при неудаче
  дёргает разлогин. Репозитории и блоки про это не знают; готовый предикат для проверки —
  `isUnauthorizedStatusCode` в `api_repository.dart`;
- одновременный рефреш из нескольких запросов должен схлопываться в один (иначе
  параллельные 401 сожгут refresh-токен);
- разлогин — это событие приложения: чистка хранилищ + `_go` на стартовый экран.

## Логирование

`LoggingInterceptor` — единственное место, где печатаются запросы.

- в `prod` полные тела и заголовки не печатаются;
- `Authorization`, токены, пароли, платёжные данные не печатаются **никогда**,
  ни в dev, ни в Crashlytics;
- `debugPrint` с телом ответа в репозитории или блоке — запрещено, для этого есть
  интерсептор.

## Чего не делать

- не писать свой `try/catch` вокруг `handleAPICall`;
- не возвращать из репозитория `null` вместо ошибки — теряется причина;
- не «чинить» кривой JSON руками через `dynamic`: безопасные конверсии — extension'ы в
  `core/extensions/num_extensions.dart` (`extensions.md`);
- не отправлять пользовательские строки из репозитория: тексты ошибок берутся из ARB на
  стороне экрана (`errors.md`);
- не добавлять второй HTTP-клиент (`http`, `chopper`) — транспорт один.

## Чек-лист

- [ ] `baseUrl` и таймауты — из флейвора/констант, не литералами;
- [ ] метод возвращает `Future<Result<DomainType>>`, исключения наружу не летят;
- [ ] `validateJson` заполнен, если бэк умеет 200-с-ошибкой;
- [ ] запрос, который может устареть, отменяем;
- [ ] пагинация: страница в стейте, `isLoadingMore` отдельным полем;
- [ ] секреты не попадают в логи;
- [ ] репозиторий зарегистрирован в DI как `lazySingleton`;
- [ ] `flutter analyze` чисто, `build_runner` прогнан при изменении моделей.
