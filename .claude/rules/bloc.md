# Правила: блоки

`screens.md` описывает блок как часть экрана: стейт со `screenStatus`, события, ui-эффекты.
Здесь — всё остальное, что к экрану не сводится: жизненный цикл, конкурентность,
подписки, связь между блоками.

Противоречий между файлами нет: `screens.md` — про структуру, `bloc.md` — про поведение.

## 1. `emit` после `await`

Между `await` и `emit` экран может закрыться. Обращение к закрытому блоку — исключение
в проде и падающий тест.

```dart
final result = await _repository.load();
if (emit.isDone) return;          // ✅ обработчик события
emit(state.copyWith(...));
```

- внутри обработчика (`Emitter` под рукой) — `if (emit.isDone) return;`;
- вне обработчика (колбэк, подписка, таймер) — `if (isClosed) return;`;
- `emitUiEffect` проверяет `isClosed` сам — дублировать не нужно.

Не эмитить из обработчика после его завершения (сохранил `emit` в поле — ошибка).
Нужно эмитить по событию извне — это `add(...)` нового события, а не отложенный `emit`.

## 2. `close()` — обязателен, если что-то заведено

Всё, что живёт дольше одного обработчика, освобождается:

```dart
@override
Future<void> close() {
  _debouncer.dispose();
  _cancelToken?.cancel();
  _subscription?.cancel();
  return super.close();
}
```

| Завёл | Освободи |
|---|---|
| `StreamSubscription` | `cancel()` |
| `Timer` / `Debouncer` | `cancel()` / `dispose()` |
| `CancelToken` | `cancel()` |
| `TextEditingController` в блоке | **не заводить** — контроллеры живут в `StatefulWidget` (`screens.md`) |

`super.close()` — последней строкой.

## 3. Конкурентность событий

По умолчанию bloc обрабатывает события **последовательно**, но не отбрасывает и не
перезапускает их. Для событий, которые пользователь может выпустить пачкой, поведение
задаётся явно — параметром `transformer` у `on<Event>`.

| Событие | Поведение | Почему |
|---|---|---|
| Поиск по мере ввода | `restartable()` | нужен только последний запрос |
| Кнопка «отправить», «купить», «сохранить» | `droppable()` | двойной тап не должен слать два запроса |
| Догрузка страницы | `droppable()` | скролл триггерит много раз подряд |
| Последовательные изменения (переключатели, сортировка) | по умолчанию | порядок важен |

`transformer` требует пакета `bloc_concurrency` — он добавляется по согласованию
(`CLAUDE.md` §3). Без него та же защита пишется руками: флаг `isSubmitting` в стейте и
ранний `return` в обработчике. Способ выбирается по ситуации, **наличие защиты
обязательно**: незащищённая кнопка отправки — это дубли на бэке.

## 4. Дебаунс

Дебаунс ввода — **в блоке**, не в виджете.

```dart
on<QueryChanged>((event, emit) {
  emit(state.copyWith(query: event.query));      // поле обновляется сразу
  _debouncer.run(() => add(Search(query: event.query)));
});
```

- виджет на каждый символ шлёт `QueryChanged` и больше ничего не знает;
- задержка — из `DurationConstant`, не литералом;
- `Debouncer` — хелпер в `lib/core/helpers/` (`helpers.md`), не приватный `Timer` в блоке;
- пустой запрос после дебаунса не улетает в сеть;
- предыдущий запрос отменяется `CancelToken`, иначе ответ на «ea» перезатрёт ответ на
  «easy» (`network.md`).

## 5. Связь между блоками

**Блок не знает о другом блоке.** Ни `sl<OtherBloc>()`, ни ссылки, ни `BlocListener`,
который дёргает соседний блок.

Связь идёт через общий источник:

```
BlocA ──изменил──▶ Repository / Service ──Stream──▶ BlocB ──add(событие)──▶ emit
```

- сервис отдаёт `Stream`, блок подписывается в конструкторе и `add`-ит событие
  (не `emit` напрямую из колбэка — иначе событие не видно в логах и не тестируется);
- подписка отменяется в `close()`;
- типовой пример: сменили язык или тему в настройках — экраны, которым это важно,
  узнают из `LanguageService`/`ThemeService`, а не из `SettingsBloc`.

Исключение — блок, явно объявленный долгоживущим (`di.md`): его читают через
`context.read<PlayerBloc>()` из UI и шлют ему события, но и он не тянется в другой блок.

## 6. Стейт

Дополнение к `screens.md` §2:

- стейт — **иммутабельный** freezed-класс. `List` внутри не мутируется на месте
  (`state.items.add(x)` не вызовет перерисовку — ссылка та же), а пересоздаётся:
  `copyWith(items: [...state.items, x])`;
- поля с «невозможными комбинациями» не заводить: если два флага не могут быть `true`
  одновременно — это одно поле-enum;
- в стейте **нет** `BuildContext`, контроллеров, виджетов, `AppError`, DTO бэка;
- в стейте лежат **готовые к отрисовке** данные: отфильтрованный список, посчитанная
  сумма, собранная строка. Вычисление в `build()` — нарушение `screens.md` §6;
- стейт, растущий за ~10 полей, обычно означает два экрана в одном или несгруппированные
  поля (`FormFields`-подобъект).

## 7. События

- события — `sealed class` в `<screen>_event.dart` как `part of` блока;
- имя события — **что произошло**, а не что сделать: `ItemTapped`, `QueryChanged`,
  `RetryPressed`. Не `LoadItems`, не `SetLoading`. Исключение — стартовое `Start<Screen>`;
- событие несёт минимум данных: id вместо всей модели, если модель уже в стейте;
- одно событие = один `on<>`, тело — в приватном методе;
- события не создаются в блоке ради «переиспользования» другого обработчика. Явная
  цепочка (`Start<Screen>` → `add(LoadData(...))`) допустима, если она очевидна из имён.

## 8. Аналитика

Трекинг вешается **на обработчик события в блоке**, не на `onTap` виджета
(`analytics.md`). Причина та же, по которой клик идёт через событие: намерение
пользователя — одна точка, где считается всё.

## 9. Не-экранные блоки

Блок без экрана (плеер, синхронизация, авторизация) — тот же `BaseBloc`, те же правила,
но:

- ему всё равно нужен `screenStatus` (ограничение `BaseBloc`) — используется значение,
  отражающее готовность самого блока;
- ui-эффекты у него есть только если кто-то их слушает; иначе — только стейт;
- регистрируется `lazySingleton`, живёт с приложением, `close()` фактически не зовётся —
  тем важнее, чтобы подписки не текли.

Заводится по согласованию, а не по умолчанию.

## Чек-лист

- [ ] после `await` перед `emit` есть `emit.isDone` / `isClosed`;
- [ ] всё заведённое освобождается в `close()`, `super.close()` последней строкой;
- [ ] события-«кнопки» защищены от двойного срабатывания;
- [ ] поиск/фильтр с сетью — с дебаунсом и отменой предыдущего запроса;
- [ ] нет обращений к другому блоку;
- [ ] стейт иммутабелен, коллекции пересоздаются;
- [ ] в стейте нет контекста, контроллеров, `AppError`, DTO;
- [ ] имена событий — про произошедшее, а не про действие.
