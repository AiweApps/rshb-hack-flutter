# Правила: аналитика и Crashlytics

Аналитика и сбор крашей — `firebase_analytics` и `firebase_crashlytics`, оба через
собственный сервис в DI.

## 1. Где вызывается трекинг

**Только в блоке, в обработчике события.** Не в виджете, не в `onTap`, не в репозитории,
не в роутере.

```dart
// ❌
onTap: () {
  Analytics.log('track_tap');
  context.read<HomePageBloc>().add(TrackTapped(track: track));
},

// ✅ виджет
onTap: () => context.read<HomePageBloc>().add(TrackTapped(track: track)),

// ✅ блок
Future<void> _trackTapped(TrackTapped event, Emitter<HomeState> emit) async {
  _analytics.log(AnalyticsEvents.trackOpened, {'track_id': event.track.id});
  emitUiEffect(OpenTrackDetails(track: event.track));
}
```

Причина та же, что у правила «клик — всегда через событие блока» (`screens.md` §6):
намерение пользователя — одна точка. Как только трекинг переехал в виджет, он дублируется
при каждом переиспользовании виджета и теряется при рефакторинге вёрстки.

Исключение — `screen_view`: он вешается один раз на роутер
(`GoRouter.observers` + `FirebaseAnalyticsObserver`), а не в каждом экране.

## 2. Сервис, а не статика

Аналитика — сервис в DI (`AnalyticsService`), не глобальный статический класс:

- его можно выключить флейвором (`analyticsEnabled`, `flavors.md`) в одном месте;
- его можно подменить в тестах;
- он инкапсулирует Firebase — фичи не импортируют `firebase_analytics`.

Метод один: `log(String event, [Map<String, Object?> params])`. «Умных» перегрузок
под каждое событие не нужно.

## 3. Имена событий и параметров

- имя события — **константа в `AnalyticsEvents`** (`app_constants.dart`), не строка на
  месте вызова. Строковый литерал события — нарушение `constants.md`;
- формат имени: `snake_case`, `<объект>_<действие>` в прошедшем времени —
  `track_opened`, `search_performed`, `settings_language_changed`. Не `click1`,
  не `onTrackTap`;
- параметры — тоже `snake_case`, значения примитивные (`String`, `int`, `bool`, `double`).
  Ни моделей, ни списков, ни JSON-строк;
- у одного события — стабильный набор параметров. Меняется набор → это новое событие,
  иначе аналитика в дашборде разъедется;
- ограничения Firebase (длина имени, число параметров) — это не рекомендация: событие,
  которое не пройдёт валидацию, просто не дойдёт.

## 4. Что нельзя отправлять

**Никогда:** email, телефон, имя, адрес, токены, пароли, точные координаты, содержимое
сообщений, платёжные данные.

**По умолчанию нет, только по явному решению:** поисковые запросы, названия открытых
объектов, любой пользовательский ввод. Вместо самого запроса отправляется его длина или
факт («поиск выполнен»), если это отвечает на вопрос продукта.

Идентификатор пользователя — только внутренний id, никогда не email.

Правило простое: **если по значению можно узнать человека или войти вместо него —
оно не идёт в аналитику.**

## 5. Crashlytics

| Что | Как |
|---|---|
| Необработанные исключения | `runZonedGuarded` + `FlutterError.onError` в `main()` — одна точка |
| Ошибки бэка 4xx/5xx, `ParsingError` | non-fatal, из блока или интерсептора (`errors.md`) |
| Нет сети, таймаут, отменённый запрос | **не логируется** |
| `RenderFlex overflowed`, падение загрузки картинки | не логируется — классификация в `FirebaseExceptionHandler` (`misc.md`) |
| Провал миграции БД | non-fatal + логи (`storage.md`) |

К нефатальным записям добавляется контекст, по которому баг воспроизводим: экран,
эндпоинт, код ответа, `keyPath` парсера. **Не** добавляется: тело ответа целиком,
заголовки, персональные данные.

`FirebaseExceptionHandler` — единственное место, где решается, что нефатально. Условие
внутри `main.dart` или внутри блока — нарушение.

## 6. Выключение в dev

Отправка событий и крашей в dev-флейворе по умолчанию **выключена** — иначе тестовые
прогоны портят продуктовую статистику, а отладочные исключения засоряют Crashlytics.
Переключатель — `analyticsEnabled` из флейвора, проверяется внутри сервиса, а не на
каждом вызове.

## Чек-лист

- [ ] трекинг вызывается из блока, не из виджета;
- [ ] имя события — константа в `AnalyticsEvents`;
- [ ] имя в `snake_case`, `<объект>_<действие>`;
- [ ] параметры примитивные, набор стабильный;
- [ ] персональных данных в событиях нет;
- [ ] нефатальные ошибки классифицируются в `FirebaseExceptionHandler`;
- [ ] в dev отправка выключена флейвором;
- [ ] фича не импортирует `firebase_*` напрямую.
