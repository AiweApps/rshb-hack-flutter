# Правила: тесты

## Позиция проекта

**Тесты пишутся только тогда, когда задача про тесты.** «На всякий случай», «заодно
покрою» и «раз уж я здесь» — не пишутся (`CLAUDE.md` §3). Тестов в проекте сейчас нет,
и это осознанно: пока архитектура и правила дозревают, тесты фиксировали бы то, что ещё
меняется.

Правило описывает, **как** писать, когда попросят, — чтобы первый же тест не пришлось
переделывать.

## Что тестировать в первую очередь

Порядок отдачи для этого проекта:

| Что | Чем | Почему первое |
|---|---|---|
| Блоки | `bloc_test` | вся логика приложения по правилам живёт там |
| Extension'ы и форматтеры | `test` | чистые функции, тест дешевле, чем ручная проверка |
| Репозитории (разбор ответа, `validateJson`, ошибки) | `test` + мок `ApiService` | ловит расхождения контракта |
| Виджеты | `flutter_test` | только сложные общие виджеты из `core/widgets/` |
| Экраны целиком | — | не тестируются: по правилам это вёрстка без логики |

Если экран приходится покрывать widget-тестом ради логики — это сигнал, что логика
осталась в UI и нарушен `screens.md` §6.

## Где лежат

Зеркально `lib/`:

```
test/
  core/extensions/format_extensions_test.dart
  features/home/application/bloc/home_bloc_test.dart
  features/home/domain/music_api_repository_test.dart
```

Имя файла — `<исходник>_test.dart`. Тесты вне этой структуры не заводятся.

## Как писать

- **Одно ожидание — один тест.** Имя теста — предложение: «emits error state when
  repository fails», не «test1»;
- структура `arrange / act / assert`, комментариями не размечать — видно по коду;
- `bloc_test`: `build` → `act` → `expect`. Проверяется **последовательность стейтов**,
  а не только финальный: пропущенный `loading` — это баг UX;
- моки — руками (простые фейки-классы) либо `mocktail`. Пакет добавляется по
  согласованию (`CLAUDE.md` §3), как и любой другой;
- реальная сеть, реальный `SharedPreferences`, реальный Firebase в тестах не используются:
  фейк подставляется через DI. Именно ради этого в правилах запрещены глобальные статические
  синглтоны (`di.md`);
- `sl` в тесте регистрируется в `setUp` и чистится `sl.reset()` в `tearDown` — иначе тесты
  начинают влиять друг на друга;
- время и случайность (`DateTime.now()`, `Random`) в тестируемый код не зашиваются:
  приходят параметром или из сервиса, иначе тест плавающий;
- тест не зависит от локали и таймзоны машины.

## Чего не делать

- не покрывать геттеры, `copyWith` и сгенерированный код — там нечего ломать;
- не гнаться за процентом покрытия: он не отличает полезный тест от бессмысленного;
- не писать тест, который повторяет реализацию строка в строку — он ломается при любом
  рефакторинге и ничего не ловит;
- не оставлять `skip: true` в коммите: либо тест работает, либо его нет.

## Команды

```bash
flutter test
flutter test test/features/home/application/bloc/home_bloc_test.dart
flutter test --coverage
```

`flutter test` обязан проходить целиком перед сдачей задачи, в которой были тесты.
