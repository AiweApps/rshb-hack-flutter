# token — завести токен дизайн-системы

Каждый токен в этом проекте живёт не в одном месте, а в четырёх-шести. Пропущенная строка
не ломает сборку и всплывает позже: цвет без `lerp` не анимируется при смене темы, ключ
без `app_de.arb` роняет немецкую локаль. Этот скилл закрывает все места разом.

## Аргументы

Свободное описание того, что нужно завести. Примеры:

```
/token цвет #FFF3BD для фона бейджа Explicit в карточке трека
/token стиль 15sp w500 line-height 20 для текста тоста
/token иконка ic_heart_filled.svg — лайк в карточке трека
/token ключ "Nothing found" для пустого результата поиска
```

Тип токена выводится из описания. Не понятно — спроси одним вопросом, не угадывай.

## Шаг 1. Проверить, что такого ещё нет

**До** добавления. Дубли — главная проблема этой кодовой базы.

```bash
# цвет — искать по значению и по близким значениям
grep -n "0xFF" lib/core/constants/app_colors_constants.dart
# стиль — искать по кеглю и весу
grep -nE "fontSize|FontWeight" lib/core/constants/app_text_styles_constants.dart
# иконка
grep -n "" lib/core/presentation/app_icons.dart
ls assets/images/
# ключ локализации — искать по тексту, а не по имени ключа
grep -in "<текст>" lib/l10n/app_en.arb
```

Нашёл точное совпадение — **токен не заводится**, в отчёте: «уже есть, используй `X`».
Нашёл близкое (разница в пару единиц hex, 1sp, похожая формулировка) — это повод для
вопроса из шага 2, а не для молчаливого выбора.

## Шаг 2. Согласовать имя

Обязателен для цвета, стиля и иконки — по процедуре `.claude/rules/theme.md`, раздел
«Процедура: нужного цвета или стиля нет в токенах». В вопросе:

1. значение (hex для цвета; кегль/вес/line-height для стиля; имя файла для иконки);
2. где встретилось — файл и что именно этим оформляется;
3. ближайший существующий токен и насколько он близок;
4. 2–3 варианта имени по конвенции проекта, с обоснованием;
5. прямой вопрос: выбрать из предложенного / дать своё / «назови сам».

Все вопросы — **одним блоком**, не по одному. Ответа нет — токен не заводится, задача
останавливается на вопросе, остальное по задаче доделывается.

Для ключа локализации имя выводится механически из смысла (`emptySearchResults`,
`errorConnectionTitle`) — спрашивать нужно, только если ключ похож на существующий или
из текста не следует область.

## Шаг 3. Добавить во все места

### Цвет — `lib/core/constants/app_colors_constants.dart`

Шесть правок, все обязательны:

1. поле `final Color <name>;` — в свою группу, по возрастанию шкалы;
2. параметр в `const AppColors({...})` — `required this.<name>`;
3. значение в `static const light = AppColors(...)`;
4. значение в `static const dark = AppColors(...)`;
5. параметр и передача в `copyWith`;
6. строка в `lerp`: `<name>: Color.lerp(<name>, other.<name>, t)!`.

Пропуск `lerp` — самая частая ошибка: цвет перестаёт анимироваться при переключении темы,
и это не видно до смены темы.

Тёмная палитра ещё не нарисована — значение в `dark` берётся такое же, как в `light`,
и это проговаривается в отчёте.

### Стиль текста — `lib/core/constants/app_text_styles_constants.dart`

1. поле `final TextStyle <name>;`;
2. параметр в `const AppTextStyles({...})`;
3. значение в `factory AppTextStyles.from(AppColors colors)` — через приватный `_style`,
   не своим `TextStyle(...)`;
4. параметр и передача в `copyWith`.

Если стиль должен подхватываться стоковыми Material-виджетами — добавить маппинг
в `_textThemeFrom` в `lib/core/presentation/base_theme.dart`.

### Иконка — `lib/core/presentation/app_icons.dart`

1. файл в `assets/images/`, имя `snake_case`, префикс `ic_` для иконок
   (в `pubspec.yaml` регистрировать не нужно — папка подключена целиком);
2. значение в enum `SvgIconRes` (или `PngIconRes` — завести по образцу, если это первая
   растровая картинка);
3. ветка в `switch` внутри `path` — `switch` исчерпывающий, без `default`;
4. использование через `.widget(...)`.

Второй файл ради другого цвета не добавляется — перекраска через `colorFilter`.

### Ключ локализации — `lib/l10n/`

1. `app_en.arb`: ключ + блок `@key` с `description`;
2. `app_de.arb`: тот же ключ. Не уверен в переводе — проставь и **явно скажи об этом**;
3. подстановки — через `placeholders`, счётчики — через `plural` (`localization.md`);
4. пересобрать: `flutter gen-l10n`.

## Шаг 4. Использовать на месте

Если в описании было указано место использования — подставить токен туда же:
`context.colors.<name>`, `context.ts.<name>`, `SvgIconRes.<name>.widget(...)`,
`context.localization.<key>` (в блоке — `lsl10n.<key>`).

## Шаг 5. Проверить

```bash
flutter gen-l10n        # если менялись ARB
flutter analyze
```

`No issues found!` — обязательно.

## Отчёт

- что заведено и с каким значением;
- полный список изменённых мест (по строке на файл);
- где токен уже используется;
- для цвета — что значение в `dark` продублировано со `light`;
- для перевода — какие строки нужно выверить носителю языка;
- открытые вопросы по именам, если ответа не было.
