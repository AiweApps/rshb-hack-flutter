# migrate-screen — привести экран к правилам

Экран, написанный одним файлом с `_build…`-методами и навигацией из `onTap`, переводится
в структуру `.claude/rules/screens.md` **без изменения поведения**. Это рефакторинг:
пользователь не должен заметить ничего.

## Аргументы

Имя экрана или путь к файлу:

```
/migrate-screen home
/migrate-screen lib/features/track_detail/presentation/track_detail_page.dart
```

Не указано — спроси, какой экран. Не бери несколько экранов за раз: один вызов — один
экран, иначе дифф невозможно проверить.

## Перед началом

Прочитай целиком: `.claude/rules/screens.md`, `bloc.md`, `errors.md`, `navigation.md`,
`widgets.md`. Затем — сам экран и его блок, полностью, до первой правки.

Выпиши для себя: какие данные рисуются, какие действия есть, что происходит при ошибке,
что при пустом результате. Это список, который должен сохраниться один в один.

## Порядок

### 1. Стейт

- `implements BaseBlocState`, поле `screenStatus`; флаги `isLoading`/`hasError` убрать;
- добавить `errorType`, если экран умеет показывать ошибку (`errors.md`);
- добавить поля под то, что UI сейчас **вычисляет сам**: отфильтрованные списки, собранные
  строки, посчитанные значения. Стейт хранит готовое к отрисовке;
- обновление поверх контента — `isRefreshing` / `isLoadingMore`, а не `loading`.

### 2. Блок

- каждое действие из UI получает своё событие: `<Что>Tapped`, `<Что>Changed`;
- навигация, диалоги, ссылки, шаринг — ui-эффекты в `<screen>_uieffect.dart`;
- вычисления, перенесённые из UI, — в обработчики;
- заведённые подписки, таймеры, дебаунсер — освобождать в `close()`;
- поиск с сетью — дебаунс и отмена (`bloc.md`).

### 3. Файлы

Из одного файла получается четыре плюс `components/`:

```
presentation/<screen>/
  <screen>_page.dart      Scaffold + BaseBlocPresentationListener + switch по статусу
  <screen>_content.dart   UI успешного состояния
  <screen>_loading.dart   загрузка
  <screen>_error.dart     AppErrorWidget по state.errorType
  components/             каждый бывший _build… — классом сюда
```

- каждый приватный `_build…`-метод становится **классом**: мелочь — приватным
  `class _X extends StatelessWidget` в том же файле, всё остальное — в `components/`;
- компоненты не знают о блоке: данные через конструктор, действия через колбэк;
- пустой результат — отдельный виджет по `state.items.isEmpty`, а не ошибка.

### 4. Токены

Попутно в этом же экране: строки → ARB, цвета → `context.colors`, стили → `context.ts`,
числа → `AppPadding`/`AppSize`/`AppRadius`, ассеты → `app_icons.dart`, картинки из сети →
`RemoteImage`.

Нужного токена нет — **не выдумывать**: собрать вопросы и задать одним блоком
(`/token` делает это по своей процедуре). Пока ответа нет — остальное доделать.

### 5. Навигация и DI

- `context.go/push/pop`, `sl<AppRouter>()` из UI убрать — переход идёт ui-эффектом
  (`navigation.md`);
- проверить, что блок регистрируется `registerFactory`, а `BlocProvider` создаётся
  в билдере маршрута, а не в странице (`di.md`);
- если экран лежал в `presentation/pages/` — переехать в `presentation/<screen>/`
  и поправить импорты.

## Чего не делать

- **не менять поведение.** Другой текст, другой отступ, другой порядок элементов — это
  уже не миграция. Заметил баг по дороге — напиши в отчёте, но не чини;
- не переписывать соседние экраны «заодно»;
- не трогать сетевой слой и модели: если экрану не хватает данных, это отдельная задача;
- не добавлять новые фичи и не удалять существующие, даже если они выглядят лишними.

## Проверить

```bash
dart run build_runner build --delete-conflicting-outputs   # стейт менялся
flutter analyze
```

`No issues found!`, затем чек-лист `.claude/rules/screens.md` §8 по своему коду.

Прогони `/check` по диффу — миграция обязана закрывать нарушения, а не переносить их
в новые файлы.

## Отчёт

- какие файлы созданы, какие удалены, что куда переехало;
- как изменился стейт: какие поля добавлены и что в них лежит;
- какие события и ui-эффекты заведены;
- какие компоненты вынесены;
- что осталось невыполненным и почему (например, ждёт имени токена);
- **явно**: изменилось ли что-нибудь в поведении. Ответ по умолчанию — «нет».
